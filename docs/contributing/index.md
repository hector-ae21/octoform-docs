# Contribute to the documentation

Documentation changes use the same review standard as application changes. A
procedure must be accurate for the version it names, safe to follow, and useful
without requiring the reader to inspect Octoform's implementation.

## Before opening a pull request

1. Check whether the change describes released behavior.
2. State prerequisites, permissions, applicability, result, and recovery.
3. Use fictitious owners, repositories, tokens, and file paths.
4. Run the complete local verification command.
5. Inspect the generated site in both light and dark modes at mobile and desktop widths.

See the repository [contribution guide](https://github.com/hector-ae21/octoform-docs/blob/HEAD/CONTRIBUTING.md)
for environment setup, commands, and the review checklist.
